# 共有範囲確認キューの修正

## 根拠

提供ログ `snapbar-1789005242191-23180-6.log`（beta.169、2026-09-10 08:02:28–10:54:01 JST）では、IdleからWaitingForShareへの遷移49回、要求送信エラーの記録56回、確認タイムアウトの記録47回を確認した。復旧画像を確認できた48例中33例で、直前と復旧後の画像サイズ・切り抜き矩形が一致した。途中のすべての状態が不変だったことまでは証明しない。

旧実装は変更通知と確認要求で容量2のチャネルを共有し、確認への応答直後も次の要求を確認せず背景探索を実行していた。タイムアウト済みの待機要求も処理していた。

## 修正

- 通知は種類別カウンターへ集約し、確認要求の枠を使わない。UIAのrevisionは通知ごとに即時失効する。
- 撮影確認、フレーム確認、背景探索の順で処理する。各確認キューは最大2件、背景確認は750ms以上の間隔とする。
- 要求の待機期限は従来の1200msを維持し、期限切れの要求を取り出した場合はUIAを実行しない。
- キュー待ち、確認実行、全探索の理由・時間、構造変更とIsOffscreen変更の件数を記録する。通知コールバックからUIAの追加問い合わせは行わない。
- 現在の権威的UIA領域の検証、出力直前の検証、失敗時のキャッシュ失効を維持する。

## 検証と限界

- 2万件の変更通知が撮影要求を押し出さず、撮影要求が先に処理されること、期限切れ要求がスキップされることを回帰テストで確認。
- fmt、Clippy、240件のテスト（4件の手動テストは除外）を通過。
- release buildと実行ファイルの起動を確認。会議未検出の通常起動でUIが非表示、プロセス応答あり、会議監視の初期化成功をログで確認した。今回の端末では共有中の実機検証は行っていない。
- 実行中のCOM呼び出しは中断しない。呼び出し中に届いた要求はその完了を待つ。UIA側の遅さそのものや通知の発生元をこの修正だけで解決したとは扱わない。
- 別端末でのオレンジ化・撮影遅延の改善量は新インストーラーのログで確認する必要がある。
