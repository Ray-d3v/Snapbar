Windows 11向けSnapbarのタイトルバー診断改善用ベータです。前回の診断版で必要な情報が残らなかった不備を修正しました。アイランド縮小そのものの修正版ではありません。

## 今回の変更

- 親要素を12階層まで探索してもTeamsウィンドウのルートに届かず、取得した親・上部要素の情報をすべて捨てていた経路を見直しました。
- 親探索より先に、選択中Teamsウィンドウの子孫要素を既存UIA APIで一括取得し、会議操作行より上の矩形を`relation=scoped_header`として記録します。親探索の失敗だけを理由に、この独立した上部情報を捨てません。
- 親探索は64階層までとし、上限と同じ階層にあるルートを確認できない境界条件も修正しました。所属を確認できない親の記録・子探索は許可しません。
- `caption_tree_begin schema=2`、`caption_tree_header`、`caption_tree_path`に、取得件数・上部要素数・親経路の到達成否・打切り理由を記録します。
- 深い親経路、上限ちょうどのルート、無関係な根・循環、時間予算、実測48pxの追加領域、COMキャッシュ設定の6件のテストを追加しました。

## 取得手順

1. Snapbarを終了し、`Snapbar-Setup-x64.exe`を上書きインストールして起動します。
2. 同じTeams会議・同じ倍率・同じウィンドウ位置のまま、デモONで共有前の正常状態を30秒以上維持します。
3. 自分の画面共有を開始し、会議本体のアイランドが小さくなった状態を30秒以上維持します。会議本体は最小化せず表示してください。
4. 通知領域のSnapbarを右クリックし、「ログを開く」で取得したログを保存します。PowerShellや実行ポリシーの変更は不要です。

## 制約

診断は既存の色取得ワーカーで原則30秒間隔、対象や境界取得成否の変化時も最短5秒間隔で実行します。追加のスレッド・依存ライブラリ・ネットワーク通信はありません。倍率・配置・ホバー・撮影範囲・出力許可の判定は変更せず、診断結果を座標補正へ使いません。実機Teamsでの新しい診断取得は未確認です。

一括取得後に処理する要素は最大2,048件、上部要素ログ64件、全ノードログ160件です。キャッシュ読み出し100msとUIA呼び出し間500msは協調的な予算であり、単一のUIA呼び出しを中断したり、APIが返す全要素数・メモリにハード上限を保証したりするものではありません。診断中はタイトルバーの色・倍率の反映が遅れる可能性があります。取得結果は原子的な観測として扱いません。

追加診断は表示名・本文・画像・クリップボード内容を取得しませんが、AutomationIdは最大80文字で記録します。動的な値が含まれる可能性があるため、共有前にログを確認してください。外部送信はしません。

配布ファイルは従来どおりコード署名されていません。企業端末のアプリ実行制限を解除するものではありません。
